## 1. 目的と、問題の形

- **目的**：誤った読みに対して「その読みは違う」と、精度高く指摘する。推論時に動くのはローカルのモデル（Luna、将来は GLM・DeepSeek・MiniMax）だけ。Sol の知識は、事前に用意する形で使う。

  - 13件の主因の内訳は次のとおり。
    - 奥行き・3次元構造の見誤りが9件：中空か中実か、厚みと広がり、貫通か止まりか、開いているか閉じているか。
    - 輪郭の取り違えが3件。
    - 作るほうの誤りが1件。
- **誤りの型の語彙**：判定（Sol）は、誤りごとに「どの問いを間違えたか」を決まった語彙で出す（`zeroshot/pipeline/retrieval/mistakes.py` の `QUESTIONS`）。
  - 判定を2回行うと、特徴ごとの誤りの有無は 351/370 で一致した。
  - 両方の判定で誤りとされた特徴では、問いが 110/129 で一致した。

## 2. ほぼ確定した事項（データで示されたこと）

### 2.1 文面だけで誤りの場所を当てる方式は、すべて失敗した

疑問（警告）の精度、つまり出した疑問のうち本当の誤りだった割合は、どの方式でも低かった。

| 方式 | 精度 |
|---|---|
| 説明文の埋め込みで、過去の誤りを引く RAG | 5% |
| 正しい読みも DB に入れた近傍法 | 最大 10% |
| キーワードで問いを出すチェックリスト | 5〜7% |
| 同じモデルによる読み直し | 10%（21 問中、正しく答えたのは 7 問。同じモデルは同じ誤りを繰り返す） |
| 場所を指さない決定木（観察は Luna） | 3〜6% |

- 説明文からは、どの特徴が誤っているかがほとんど分からない。
- DB を大きくしても、伸びは小さかった（部品数を倍にするごとに約 2 点）。

## 3. 今のアルゴリズム（推論時の流れ）

> 2.8 の最終構成で、印は「穴の辺」と「空洞の壁」の2種類になった（`grounded.py` の `KINDS`）。下の印の説明のうち、穴の帯・面の帯・内壁の線・本体の塗りは旧版。穴は辺ごとの結論を `hole_doubt`（2本以上か全部が線なし）でまとめる。

1. コーダーが interpretation.json を書き、ビルドが検証される。ここで `drawing_to_model_uv` ができる。
2. **印の取り出し**（`marks.py`）：ローカルのモデルが、読みの parameters から次の 3 種類を決まった形で出す。
   - 穴：中心、軸、断面の幅、読みの主張（貫通か止まり）。
   - 本体：軸にそろった箱、中実かどうか。
   - 空洞：軸にそろった箱。
   - 同じ軸上の座ぐり・皿・段と通し穴は、1 本の段付き穴にまとめる（`stepped`）。
3. **問いの画像**（`grounded.py questions`）
   - 印ごとに、位置合わせの良いビューを選ぶ。
   - 画像は「ビュー全体（印と、拡大範囲の青枠）」と「拡大図」の組。
   - 印の種類：
     - 穴の帯：穴の幅で、その穴を含む本体の範囲を軸方向に通す。読みの主張は描かない。軸方向のビューでは、口の輪郭を描く。
     - 面の帯：本体の向かい合う 2 面の位置。
     - 内壁の線：空洞の壁の位置。部品や本体の面と重なる面は開口とみなし、壁としては問わない。
     - 本体の塗り：読みが中実とする本体。
4. **観察**（`grounded.py observe`）
   - ローカルのモデルに、印の説明と木の問いを渡す。問いは、線の様子だけを聞く短いもの。
   - 読みの文面は見せない。
   - 問いは 1 問ずつ聞き、次の問いはプログラムが木をたどって決める（1 つの会話の中で続ける）。2026-10-25 までの 2.6 の結果は、印 1 つの木の問いをまとめて 1 回で聞いた版のもの。
   - 1 問ずつの版（パイロット 25 件、Luna、`analysis_100/grounded_v2_step/`）：疑問の一致 10/62（まとめて聞いた版 12/73）、穴の帯 2/2（同じ）、拾えた判定の誤り 4/20（同 6/20）。結論が同じだったのは 355 問中 270 問で、同じ方式を繰り返していないので、差が方式によるものか揺らぎかは分からない。1 回の読みあたり、呼び出し 38.7 回（同 14.2）、入力 7.4 万トークン（同 2.4 万）。
   - 採点の注意：面の帯の「一致」は、特徴と誤りの型だけで数えている。draw_0743 の板の一致 2 件は、正面図の縦横の広がりへの疑問で、判定の誤り（厚み、側面図でしか見えない）を指してはいない。面の帯の一致は目で確かめること。
5. **結論と疑問**
   - プログラムが木をたどって結論を出し、読みの主張と食い違ったときだけ疑問にする。
   - 縮尺の食い違い（ビュー間 1.2 倍超）も疑問にする。
6. **コーダーへの返し方**（未実装）：根拠を添えた問いの形にする。
   - 例：「底面図では、この穴の側面の線が後面の手前で横線に当たって止まって見えます。この穴は本当に後面まで抜けていますか」

**木の作り方**（`trees.py grounded`、`tree_tests.py`）

- Sol が、印の種類ごとに観察の木を書く。材料は、判定の誤りに残った「決め手の線」と、紛らわしい形の一覧。
- 部品を 2 つの分割に分ける。片方の部品の最初の読みから作った木を、もう片方の部品に使う。
- 正解の分かっている 29 の場面を文章で与え、Sol を観察者として木の論理をテストした。誤った結論が出た木は、失敗例を添えて Sol に直させた。今は 8 本すべてが全場面を通る。

## 4. 検討中の課題

1. **本体の印で誤報が多い**（面の帯 9/47、本体の塗り 0/16）。画像で確かめた原因は 3 つ。
   - 軸にそろった箱が、曲がった本体や複雑な本体に合わない。隣の特徴の外形を本体のものと取り違える例もあった（draw_0753）。
   - 本体の塗りが、読み自身が別の特徴として持っている空洞まで覆う（007126 の裏ポケット）。
   - 取り出しの誤り：004278 の「両端が開いた通しの空洞」を、閉じた箱にしていた。
2. **Luna が穴で「判断せず」に倒れやすく、拾える割合が低い**（Sol 3/5、Luna 1/5）。原因はまだ調べていない。
3. **穴として取り出されない穴がある**：枠の一部の開口、面のスロット、長円の溝。
4. **評価の基準**：判定（Sol）の誤りとの一致で数えている。そのため、判定が拾っていない本当の誤りへの疑問も「外れ」に入る。外れの目視確認はまだ一部。
5. **隠れ線を描かない図面**（IterCAD）：穴の帯の木は、ほとんど「判断せず」になる。

## 5. 今後の実装・実験の予定

1. **本体の印の作り直し**：箱の代わりに、ビルドそのものの投影の辺を使う。
   - ビルドの投影（`attempts/.../projection/<view>.dxf` は UV 座標 mm で、見える辺と隠れ辺がある）を、`drawing_to_model_uv` でピクセルに写す。
   - 辺を 1 本ずつ印にして、「ここにビルドの隠れ辺（または見える辺）がある。図面のこの位置に破線（実線）はあるか」と問う。
   - 箱が合わない問題と、読み自身の空洞を覆う問題は、構造的に消える。004278 のような、差分の許容範囲に埋もれる違いを拾う狙い。
   - 決めること：
     - どの辺を問うか。辺の数だけ問いが増えるので、特徴の印に近い辺、長い辺、隠れ辺を優先して絞る。
     - 辺を特徴に結び付ける方法。読みの座標に近いものを選ぶ。
     - 新しい印の種類（辺の線）の木と、そのテスト場面。
   - 当面の手直し：本体の塗りは、読みの空洞や穴を含む本体には使わない。
   - 注意：辺を特徴に結び付けず、木も通さずに「ビルドと図面の線の食い違い」だけを出すのは、既存の図面比較（directional chamfer で位置合わせした後の unmatched）の厳しい版にすぎず、読みの誤りの指摘にならない。評価も 2.6 と同じく、疑問が判定の誤りと一致したかで数える。（2026-10-25 に一度これをやって外した。）
2. **100 件で通しの検証**：1 の後、Sol（正解を見ない）と Luna で全問を回す。疑問の精度・再現率・コストを、印の種類ごとに出す。疑問は全件、画像で目視確認する。
3. **Luna の「判断せず」の原因調査**：穴の木のどの問いで止まっているかを集計する。
4. **パイプラインへの組み込み**
   - 最初のビルドの検証の後、解釈の検証の返信の `questions`（解釈を拒まない疑問の経路）に、問いの形で返す。
   - その後、警告なし・ありで run を比べ、IoU・直った誤り・壊した所・ターン数を測る。
5. **モデルの乗り換え**：同じ問いを GLM・DeepSeek・MiniMax に答えさせて比べる。これらが本命。

## 6. 残っている課題とリスク

- **件数が少ない**：25 件、穴の疑問は数件。精度の数字は大きくぶれる。
- **木の材料が少ない**：各分割で、誤り 1〜8 件から作っている。テスト場面は私が文章で作ったもので、確かめたのは木の論理だけ（知覚ではない）。
- **他の図面への汎化**：Ortho2CAD や実図面（ditech）は未確認。位置合わせとビューの選択は、パイプラインの描画・照合が働く図面にしか使えない。
- **輪郭そのものの取り違え**（13 件中 3 件）：まだ印にする方法がない。
- **位置合わせに失敗したビュー**：問いに使えない。縮尺の食い違いの検査で補うが、範囲は狭い。
